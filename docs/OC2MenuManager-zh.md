# OC2MenuManager 使用说明

英文版： [OC2MenuManager.md](./OC2MenuManager.md)

## 简介

`OC2MenuManager` 是一个独立的 Overcooked! 2 菜单辅助模组。
它不依赖 `ConfigurationManager.dll` 或 `HostUtilities`。
它有自己的游戏内配置窗口。
如果安装了 `OC2DIYLevel` 或 Recipe Extension（`OC2ManyRecipes`），模组会通过受保护的可选适配器加入这些菜品，但不会把它们变成必装前置。

当前主要功能：

- 按关卡追踪菜品
- 左侧历史菜单悬浮窗
- 已备菜品识别
- 顶部真实菜单卡片上色
- 顶部额外猜单显示
- 麻团关卡相关菜单辅助
- 内置无菜单开关

## 前置条件

- `Overcooked! 2`
- `BepInEx`

## 可选模组兼容性

- 支持 `OC2DIYLevel` 0.8 风格以及新版的菜谱接口。
  - DIY 前端元数据加载完成后，模组会读取关卡及其准确的菜谱 ID/名称。
  - 不用先进入关卡，就能选择 DIY 关卡并配置追踪菜品。
  - 原版 DIY 菜谱可在前端完整读取；自定义菜谱会先按 ID/名称预载，开局后再升级成真实运行时定义。
- 支持 Recipe Extension / `OC2ManyRecipes` 1.1 的运行时菜谱。
  - 扩展模组为本局生成菜谱后，菜单管理器会把它们并入当前关卡。
  - 保留扩展模组两个特殊动态关卡的阶段筛选规则。
  - 真实订单始终保留自己的位置；只要关卡本身不超过 10 张真实订单，活动中的真实订单和猜单总数就不会超过 10。

这两个兼容项都是可选的。如果可选模组未安装，或未来版本不再提供已知反射接口，只会关闭对应兼容项，菜单管理器的独立功能仍会继续运行。

## 安装方法

最小安装：

1. 把 `OC2MenuManager.dll` 复制到以下任意位置：
   - `Overcooked! 2\BepInEx\plugins\`
   - `Overcooked! 2\BepInEx\plugins\OC2MenuManager\`
2. 启动游戏。

可选文件：

- `OC2MenuManager.pdb`
  - 不是必需文件
  - 只用于调试

## 模组会使用哪些文件

插件文件：

- `Overcooked! 2\BepInEx\plugins\OC2MenuManager\OC2MenuManager.dll`

主配置文件：

- `Overcooked! 2\BepInEx\config\OC2MenuManager.standalone.cfg`

热键文件：

- `Overcooked! 2\BepInEx\config\OC2MenuManager.hotkey.txt`

菜品追踪选择文件：

- `Overcooked! 2\BepInEx\config\OC2MenuManager.selections.txt`

可选的菜品发现报告：

- `Overcooked! 2\BepInEx\config\OC2MenuManager.dish-catalog-report.txt`

如果新选择文件不存在，模组会从旧的 `HostUtilities-ServedDishTrackerSelections.txt` 复制一次数据；旧文件不会被删除或覆盖。

## 如何打开配置窗口

默认热键：

- `F6`

热键保存在：

- `BepInEx\config\OC2MenuManager.hotkey.txt`

示例内容：

```txt
# OC2MenuManager hotkey config
# Edit the value after Hotkey= and save the file.
# Use Hotkey=None if you want to disable the launch hotkey.
Hotkey=F6
```

常见写法：

- `Hotkey=F6`
- `Hotkey=F7`
- `Hotkey=Home`
- `Hotkey=None`

改热键有两种方式：

- 在模组窗口里点击热键行直接改
- 直接编辑 `OC2MenuManager.hotkey.txt`

## 推荐的首次使用流程

1. 按 `F6` 打开模组窗口。
2. 在 `菜单追踪` 里选择关卡。
3. 勾选你要追踪的菜品。
4. 打开 `启用历史菜单追踪`。
5. 如果你想识别已备成品，打开 `启用已备跟踪`。
6. 如果你想给顶部真实菜单卡片上色，打开 `菜单颜色`。
7. 如果你想在顶部额外显示猜单，调整 `最大猜单数量`。
8. 在 `悬浮窗` 中调整位置、尺寸和字体，让左侧面板适合你的屏幕。

## 当前配置窗口分区

当前窗口包含这些分区：

- `菜单追踪`
- `历史菜单追踪`
- `层级设置`
- `功能开关`
- `悬浮窗`
- `界面`

### 菜单追踪

这一组决定模组当前允许追踪哪些菜。

你可以在这里：

- 选择关卡
- 勾选当前关卡要追踪的菜品
- 使用按类别生成的快捷按钮，比如蛋糕、汉堡、披萨等
- 使用全选、清空、刷新之类的批量操作

关卡选择的当前逻辑：

- 不在关卡内时，可以自由切换关卡
- 在关卡内时，会自动锁定为当前关卡

这个锁定是故意的，目的是避免实战中误切到别的关卡。

OC2DIYLevel 完成前端元数据加载后，DIY 关卡会自动出现。选择关卡时才会按需读取菜谱；如果元数据还没准备好，窗口会显示加载/错误状态和重试按钮。现在不需要为了配置而先进入一次 DIY 关卡。

Recipe Extension 的菜谱是在本局初始化时依据真实关卡生成的，因此开局后才会出现在当前关卡的选择列表中。如果刚修改了可选模组配置，可以按一次 `刷新`。

### 历史菜单追踪

这是最核心的一组设置。

#### 启用历史菜单追踪

- 在标准关卡中启用历史菜单追踪
- 控制左侧悬浮窗
- 也控制顶部猜单的候选来源

#### 启用已备跟踪

- 识别已经完成、但还没交出的菜
- 会影响左侧悬浮窗状态
- 会影响顶部真实菜单卡片颜色
- 也会影响猜单是否继续显示

已备跟踪会尽量识别多种来源，例如：

- 盘子上的完整菜
- 某些容器中的完整菜
- 某些角色手上的完整菜
- 某些 cooker 刚完成的菜

这项功能是模组里比较重的一块。
如果你感觉卡顿，优先尝试先关闭它。

#### 菜单颜色

- 给游戏顶部真实菜单卡片上色

颜色项包括：

- `在单颜色`
  - 当前真实在单，且还没备好的单
- `已备颜色`
  - 当前真实在单，且已经备好的单
- `猜单颜色`
  - 顶部额外插入的猜单

透明度说明：

- `A` 通道控制整张卡片的透明度
- 不只是背景，整张单都会一起变淡
- 猜单在此基础上还会额外压暗一点，让它看起来更像参考信息

#### 最大猜单数量

范围：

- `0` 到 `5`

默认值：

- `3`

含义：

- `0` 表示关闭顶部猜单
- `1-5` 表示在真实菜单后面最多额外显示多少个猜单

注意：

- 猜单只是参考，不是真实订单
- 真实订单永远在前面，猜单追加在后面
- 活动猜单数量按 `max(0, min(配置上限, 10 - 当前真实订单数))` 自动调整
- 5 张真实订单可显示 5 张猜单，6 张可显示 4 张，8 张可显示 2 张
- 如果关卡本身生成超过 10 张真实订单，所有真实订单仍会显示，猜单则降为 0

#### 显示语言

模式：

- `Auto`
- `English`
- `Chinese`

当前逻辑：

- `Auto` 跟随游戏语言
- 这个设置会同时影响菜名、分类名、配置窗口文字和悬浮窗文字

#### 关卡名称最大长度

- 控制关卡选择按钮和下拉列表里的最大字符数

#### 菜品名称最大长度

- 控制主窗口里追踪菜品列表的最大字符数

### 层级设置

这一组控制分类优先级。

当前逻辑：

- 每个菜品分类都有一个 `1` 到 `6` 的层级
- 数字越小，排序越靠前
- 点击层级按钮会循环切换数值
- `默认` 用来重置单个分类
- `全部重置` 用来重置所有分类

当前界面表现：

- 分类以五列显示
- 这样纵向不会占太多空间

层级会影响：

- 左侧悬浮窗排序
- 顶部猜单排序
- 分类分组逻辑

层级不会影响：

- 游戏真实出单
- 菜谱内容本身

这是一项按分类设置的功能，不是按单道菜设置。

### 功能开关

这一组是一些额外玩法开关。

#### 麻团好菜单

- 第一单没有葱
- 前两单不会出蛋糕

#### 麻团好蛋糕

- 提高麻团关卡里蛋糕相关菜单出现概率

#### 麻团TAS菜单

- 把麻团菜单锁成 TAS 用序列

#### 无菜单

- 设置在下一局边界生效，状态行会显示已启用、待生效或不支持原因
- 支持标准/动态剧情厨房和对战厨房
- 本局启用后关闭正常出单，并安全移除开局预生成订单
- 接受本局当前有效的菜谱；动态关卡跟随游戏当前阶段
- 支持 DIY 与 Recipe Extension 菜谱
- 保留正常得分/连击回调，并确保盘子只回收一次
- 启用期间暂停本模组的悬浮窗、已备追踪、菜单上色和猜单
- Boss、教程、生存、部落（Horde）、计时前依赖订单以及公开联机局保留正常菜单，并显示原因

### 悬浮窗

这一组控制左侧游戏内文字面板。

可调项目：

- `悬浮窗X`
- `悬浮窗Y`
- `悬浮窗宽度`
- `悬浮窗高度`
- `悬浮窗字体大小`
- `悬浮窗关卡名长度`
- `悬浮窗菜名长度`
- `悬浮窗粗体`
- `悬浮窗最大显示菜品数`
- `悬浮窗文本对齐`
- `悬浮窗字体颜色`
- `悬浮窗上单数量颜色`
- `悬浮窗概率颜色`
- `悬浮窗已备颜色`

实用建议：

- 如果文字被截断，优先调大关卡名和菜名长度
- 如果面板太挤，先降低 `悬浮窗最大显示菜品数`
- 如果面板太碍眼，可以移动位置、减小宽度或字体

### 界面

这一组控制模组自己的窗口外观。

包括：

- `MOD的UI字体大小`
  - 独立窗口和悬浮窗共用的基础字号
- `MOD的UI字体颜色`
  - 独立窗口和悬浮窗共用的基础字体颜色
- `打开菜单管理窗口`
  - 用来改设置窗口热键

## 左侧悬浮窗的显示逻辑

左侧悬浮窗是一个紧凑的待办面板。

它会显示：

- 关卡名
- 排序说明
- 图例
- 每道被追踪的菜
- 上单数量
- 下一单出现概率
- 已备数量

其中已备数量只会在 `启用已备跟踪` 时参与显示和判断。

### 图例说明

未启用已备跟踪时：

- `[   ]在单`
- `[ - ]未备`
- `[ x ]已上`

启用已备跟踪时：

- `[   ]在单`
- `[ - ]未备`
- `[ x ]已上`
- `[ v ]已备`

含义：

- `在单`
  - 当前真实菜单栏上有这道菜，而且还没备好
- `未备`
  - 当前不在真实菜单栏上、也没备好，但下一单仍有正概率出现
- `已上`
  - 当前不在真实菜单栏上，而且下一单概率已经是 `0%`
- `已备`
  - 已经做好了，但还没有成功交出

### 当前排序逻辑

悬浮窗会尽量把现在最值得处理的项目排在前面。

总体优先级：

1. 在单且未备
2. 不在单、未备、且概率大于 `0%`
3. 不在单、未备、且概率等于 `0%`
4. 已备

同类项目内，再继续按这些条件排序：

- 分类层级
- 下一单概率
- 上单数量
- 显示名称

### 当前视觉规则

- 橙色菜名表示在单未备
- 绿色菜名表示已备
- 蓝色数字表示上单数量
- 金色数字表示概率
- `0%` 行会整体变暗，并带删除线

## 顶部猜单的工作方式

猜单会出现在游戏顶部真实菜单卡片区域里，但它本身不是真实订单。

它只是参考信息，复用了游戏自己的菜单卡片 UI。

一条菜会成为猜单，必须同时满足：

- 这道菜被勾选为追踪对象
- 当前不在真实菜单栏上
- 当前没有备好
- 下一单仍有正概率出现

顶部猜单的候选顺序，来自和左侧悬浮窗 `[ - ]未备` 完全相同的排序来源。
也就是说：

- 左侧 `[ - ]未备` 的相对顺序，就是顶部猜单的相对顺序
- 顶部猜单只是这批候选里按数量截取出来的一部分

当前表现：

- 真实订单永远在前面
- 猜单追加在后面
- 新真实订单加入前，会先移除超出 10 张总上限的猜单
- 猜单失效时会消失
- 如果后面还有新的候选，就会补上来

## 语言和菜名命名

这个模组里的英文菜名是专门整理过的，目标是：

- 更接近中文的命名方式
- 尽量分类在前
- 尽量简洁
- 更适合在菜单列表和悬浮窗里快速扫读

例如：

- `Cake: Chocolate`
- `Pancake: Strawberry`
- `Burger: Cheese`

语言设置不仅影响菜名，也会影响分类名和设置窗口文字。

## 文字被截断时怎么调

如果你觉得有些文字太长，被裁掉了，优先调这些项目：

- `关卡名称最大长度`
- `菜品名称最大长度`
- `悬浮窗关卡名长度`
- `悬浮窗菜名长度`

对应位置分别是：

- 主窗口关卡选择按钮和下拉列表
- 主窗口追踪菜品列表
- 悬浮窗标题
- 悬浮窗菜名

## 性能建议

如果你觉得模组有点重，可以先按这个顺序尝试：

1. 关闭 `启用已备跟踪`
2. 关闭 `菜单颜色`
3. 降低 `最大猜单数量`
4. 降低 `悬浮窗最大显示菜品数`

原因：

- 已备菜品匹配仍是最重的可选功能
- 关卡/控制器查询已缓存，已备来源通常由事件驱动，兜底扫描会延迟并分阶段执行
- 菜单布局交给游戏本身；只有真实单/猜单成员发生变化时才调整顺序
- 大菜谱池会复用选择器分类缓存，并使用有限值与去重保护的概率计算

## 常见问题

### 热键没反应

先检查：

- `BepInEx\config\OC2MenuManager.hotkey.txt` 是否存在
- 文件里是不是写成了 `Hotkey=None`
- 是否有别的模组占用了同一个按键

### 我替换了 DLL，但游戏里没变化

先检查：

- 你复制的是不是游戏真正启动目录下的 `BepInEx\plugins`
- 复制 DLL 前游戏有没有彻底退出
- 是否还有别的 `OC2MenuManager.dll` 副本

最稳妥的流程：

1. 完全关闭游戏
2. 确认安装路径
3. 替换 DLL
4. 重启游戏

### 为什么关卡选择被锁住了

这是正常现象。
当你已经进入关卡时，模组会自动锁定到本局关卡。

### 为什么顶部猜单和真实菜单不一样

这是正常现象。
猜单不是“真实订单”，而是“有可能马上出现的参考候选”。

### 为什么画面看起来太拥挤

可以优先尝试：

- 降低 `最大猜单数量`
- 降低 `悬浮窗最大显示菜品数`
- 提高名称最大长度设置
- 调整悬浮窗位置

### DIY 关卡已经出现，但没有菜品

等待 OC2DIYLevel 完成加载，选择该关卡后点击 `重试读取 DIY 菜谱`。如果安装版本的接口不受支持，BepInEx 日志里会有一条 `[Compatibility]` 警告。

### Recipe Extension 菜品没有出现

这些菜谱是在本局初始化时生成，不会提前出现在前端。先启动关卡，按 `F6` 后点击 `刷新`；确认 `OC2ManyRecipes` 1.1 已启用，并检查 BepInEx 日志中的一次性适配器启用信息。

## 最简使用方法

如果你只想最快上手：

1. 安装 `OC2MenuManager.dll`
2. 启动游戏
3. 按 `F6`
4. 选择关卡
5. 勾选要追踪的菜
6. 打开 `启用历史菜单追踪`
7. 需要的话再打开 `启用已备跟踪` 和 `菜单颜色`

这样就足够正常使用了。
